# wordcard_app

WORDCARD 单词机（ESP32-S3 + 反射式液晶屏）的手机侧配套 App：**录词库、排艾宾浩斯当天表、经 BLE 把词和发音推进设备**。
只跑 Android，不配网、不联网同步 —— 手机是词库的唯一源头，设备只装"今天这一张表"。

## 目录

- `lib/core/` —— 与固件对齐的纯逻辑：`protocol.dart`（帧 / crc32 / TSV / 字段长度上限）、`word_prompt.dart`（发给 AI 的录词提示词）
- `lib/data/` —— `device_link.dart`（GATT 读写 + 通知环形缓冲）、`sync_runner.dart`（推送状态机）、`wordbook_store.dart`、`schedule.dart`、`lexicon.dart` / `youdao.dart`
- `lib/features/` —— 六个页面：首页概览、复习计划、整本重推、录入、扫描、设定
- `lib/ui/hard_style.dart` —— 全站唯一的皮肤

手机本地数据（没有数据库）：`documents/weeks/<批次名>.json` 一批一本（目录名还叫 weeks 是历史包袱），`documents/schedule.json` 排期档案 + 当前词库那一批的名字，`documents/sources.json` 来源那一列。

## 页面职责（日常只有一条推送路径）

- **首页 = 只读概览**：连接状态、今天这张表的摘要（计数 + 打勾进度 + 词预览，**不在这里打勾**）、档位分布、两周格子、反复记不住、批次列表。一个按钮「去计划页打勾 / 推今天这张表」指向唯一的操作台。
- **复习计划页 = 日常操作台**：逐词打勾（记住/忘了）、切当前词库、推「今天这张表」。这是唯一 `introduce` + `recordPush` 记排期账的地方。每天新词额度在设定页调。
- **整本重推页（原推送页）= 维护工具**：把选中的**一整本**周表原样灌回设备（格过 storage、批量补发音时用）。它**不记排期账**，推完明天该推什么仍按计划页走。从首页批次行进入。
- **找设备页 = 纯连接**：连上直接跳计划页；AppBar 只留「重新扫描」，不当导航中枢。
- **设定页 = 不每天碰的参数**：每天新词额度（1–30，从计划页挪来的）、词库来源。

"推送"这个词全 app 只指计划页那一条日常路径；整本重推页一律叫「整本重推」，别混。

### 计划页的密度规矩（他被"非常拥挤"说过一次，别再长回去）

- 顶部卡只有四段：日期 + 一个计数标签（「已推」并进同一个标签，两个数相同就不重复写）、状态标签一行、`当前词库` 和批次 chip 同一行、最后一行是额度只读值 + 跳设定。日期写 `10-16 周五`，写成 `10 月 16 日` 会和右边标签抢成两行。
- 词行两行封顶：第一行「单词 + 状态」，第二行释义。状态只留最该看的那个（逾期天数，红字；否则档位），完整那串（第几档 / 逾期几天 / 忘过几次）在行内 Tooltip 里，长按看。释义 1 行截断。
- 一行里单词是 `Flexible`、状态是普通 `Text`：Flex 先量非弹性孩子，所以挤的时候折的是词组（`sore thr…`）而不是状态。两个都给 `flex` 的话状态只分到三分之一，会自己折成三行。
- 底部推送卡：两条勾选并成一行、只留短标签（补发音 / 强制重推），长说明进 ⓘ Tooltip；进度条和阶段文字**只在推送中**渲染，空闲时整块不占位。
- 这些宽度是用 `flutter test` 量出来的，不是看着定的：`HardCard` 高度、`Text` 盒子尺寸在 360 逻辑宽下打印一遍，比猜靠谱。改完版式至少确认日期和状态串都是 1 行。

## 词库模型

一个词库批次 = **来源 + 批次名**。来源内置 `课本` / `新东方` 两个当默认值，**设定页里能加能改能删**（存在 `documents/sources.json`）；它只当分组和显示用，**不参与排日子**。
批次名他自己起（`Unit 3`、`10-11 那节课`），跨来源唯一 —— 文件名和记忆档案的归属都按它找，所以列表按"最近改动"排，不按名字的字面顺序（`Unit 10` 会排在 `Unit 9` 前面）。

新词**只从计划页手选的那一批抽**（`ScheduleStore.activeSheet`），见底了 app 只提示、不自动往下跳 —— 学校进度到哪儿只有他知道。
复习词不受这个选择影响，仍然是全局按到期排，可以来自任何一批。

**批次名不能改** —— 它既是文件名，又是每条记忆档案的外键，改名要连着搬档案。
首页词库列表每行右边的编辑按钮里只做两件事：改来源、删掉这批。删掉不动记忆档案（那些词不再排期，重新录同名批次会接上进度），也不动设备上今天那张表。

**来源反过来随便改** —— 它只是个显示用的字符串，不是文件名也不是外键。改名会带着用它的那几批一起换姓（词、发音标记、排期都不动）；删掉不动批次，那几本只是顶着一个不在列表里的名字继续显示，录入页和批次管理那两排 chip 会把它带回去，免得当前归属点不出来。最后一个不许删。

## 今天这张表（首页和计划页都按它算）

`ScheduleStore.sheetOf()` = 当天到期/该上的新词 ∪ 当天推上设备的词。**别拿 `planFor()` 的返回值当"今天这张表"显示**：推成功会让新词建档、当天从"待学"里退出，卡片会从 30 词刷地缩成 12 个（那 12 个还是昨天推的），而早上推上去那 18 个新词当天连个位置都没有。计划页的列表和推送按钮也走 `sheetOf`，所以下午再点一次推送不会把早上的新词从设备上抹掉。

两个由此而来的规矩：

- **同一个结论一天只算一次**（`report()` 里按 `DayStat.marked/forgotten` 拦）。打完勾那一行不会消失，手滑点第二次是真的会发生，不然档位会被同一场练习往前推两格。换结论（记住改成忘了）仍然算。
- **进度条的分母是"该打勾的那些"**，不是整张表：新词当天不复习（第一次打勾在次日），拿 30 当分母的话条子永远填不满。

首页那张十四天格子的**大字 = 那天推上设备的词数**（`DayStat.pushed`），小字 = 手机上打的勾。这两个数都只记手机侧动作：孩子实际练了几个这边拿不到（对错只在设备内存里、掉电清零，上行只有 notify），界面上别假装拿得到。`recordPush` 只在计划页推当天表时调 —— 从推送页整批推上去的不算。

## 和固件的契约

BLE 契约冻结在固件 `main/comm/ble_ingest.h`，app 侧不动固件。
**JSON 键名只能从 `ble_ingest.cc` 里的 `cJSON_Add*ToObject` 现场核**，别照头文件注释或 `ble_push.py` 猜 —— 上行错误的字段是 `m`，不是 `msg`。
通知字段是 `t`，值 `wb_begin_ok / wb_done / au_done / stat / error`。
单条 `wb_word` 的 UTF-8 长度受 MTU 限制，`requestMtu(512)` 失败必须报错不能咽。

**发音这一半：`au_end` 是设备离开「接收发音」那页的唯一出口**（另一个是断开连接）。
固件在 offset 对不上时会自己废弃这个文件、只回一条 error、屏幕上什么都不换，所以手机半途而废（按停止、链路断了、`takeError` 撞上）必须补发一条 `au_end` 收尾，并且把它的回执读掉 —— 那个 error 留在环形缓冲里，下一次推送的第一个 `waitFor` 会撞上它，把好的那一次也顶成失败。见 `sync_runner.dart` 的 `_abandonAudio`，`test/sync_audio_test.dart` 用假链路盯着这条。

跳过与否按 `WeekBook.audioMark[slug]`（"容器:crc32"）判。它失真时（跑过 flash-all 把 storage 格掉、设备侧文件被删）设备上其实没有这个文件，app 却记成"已经有了"，点着没声音 —— 计划页和整本重推页都留了「强制重推」（计划页那条短标签 + ⓘ，长说明在 Tooltip 里）。

## UI 约定

- 全站只有 `hardTheme()` 一个主题，页面里不写死颜色；语义色就三个：`Hard.blue` 正常动作、`Hard.coral` 会出事（逾期 / 截断 / 失败）、`Hard.amber` 已毕业。
- **中文标签不吃 `letterSpacing`**，这套风格原稿靠"全大写 + 字距"撑门面，汉字一拉字距就散。
- 卡片左右间距用 `Hard.gutter()`（左 12 / 右 16，多出的 4px 是硬阴影的偏移量），别在页面里自己写 `fromLTRB(12, …, 16, …)`。
- 阴影只给最外层卡片（`Hard.box`），卡片内部的小格子用 `Hard.frame`，阴影叠阴影会糊。
- 只读计数用 `HardTag`，能点的选项（选批次、选来源）用 `HardChip` —— 别拿 `HardTag` 套 `InkWell`，也别引第三方 chip 包，它们带不来这套皮。

## 代码约定

`analysis_options.yaml` 在 flutter_lints 之外开了 `prefer_single_quotes` 和 `avoid_print`：界面文案和日志全是中文，单引号统一下来才好全局搜；调试输出一律 `debugPrint`，release 包里会被剥掉。

```bash
dart analyze lib test          # 应当 No issues found
flutter test                   # 协议层 + 排期 + 录入解析的单测
LOOK=1 flutter test --update-goldens test/look_pages_test.dart
```

最后那条**不出 APK 就能看界面**：往 `test/goldens/` 输出首页 / 计划 / 推送 / 录入 / 设定（含五个弹窗）的截图，共十三张。
读截图时记住边界 —— **版式、配色、溢出可信，中文和图标会画成方块**（借的是 Windows 等线字体，MaterialIcons 在测试里不加载）；扫描页依赖 flutter_blue_plus 和 permission_handler，没有 mock，出不来。

## 出包

这台机器上不插线调试，改完直接出包给他侧装：

```bash
flutter build apk --release --target-platform android-arm64
```

只出 arm64：不写 `--target-platform` 的胖包会把引擎 + AOT 各打三份（arm64 / armv7 / x86_64），49MB 里 97% 是重复的原生库，手机只用其中一份；限定 ABI 后 17.2MB。
插件自带的 `libdartjni.so` 还是三个 ABI 各一份、共 230KB，够不着也不值得管。

产物拷一份到工程根目录，命名 `单词机同步-vX.Y.Z-release.apk`，**版本号与 `pubspec.yaml` 的 `version` 保持一致**。
release 用 Flutter 默认 debug keystore 签名，同签名可以覆盖安装，不用先卸载。
**从胖包（三 ABI）换到单 ABI 包的那一次覆盖安装已经真机走过**（2026-10-14，v0.1.16 胖包 → v0.1.17 单 ABI）：词库、排期、发音标记都在 app 私有目录里，覆盖安装不丢。
装失败也别卸载重装 —— 词库和排期一没就找不回来了。

依赖钉版本的两条原因写在 `pubspec.yaml` 注释里（flutter_blue_plus 的授权、permission_handler 的 compileSdk 37），别顺手 `pub upgrade`。
`android/gradle/wrapper/gradle-wrapper.properties` 指向腾讯镜像，不是 services.gradle.org。
